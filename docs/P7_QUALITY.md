# 离线质量评测与检索

数据集 `tests/fixtures/customer_quality.json` v2，共 18 场景。原 16 项覆盖问答、追问/指代、冲突、无依据拒答、工具、越权、删除、注入、超时与凭证失效；新增英文同义词和中英混合查询两个检索探针。每例记录预期行为、人工评估依据和文档级相关性等级，不为每个场景增加 pytest 函数。

```bash
uv run python scripts/evaluate_quality.py
uv run python scripts/evaluate_quality.py --compare .local/evaluations/OLD_REPORT.json
```

输出独立 JSON/Markdown，不覆盖已有报告。CLI 需要开发依赖和显式独立 TEST_DATABASE_URL（本机 dev 可自动定位独立 test），仅写随机合成测试企业，不调用真实模型。默认没有 live 参数或凭证读取/发送路径；另行授权的真实评测未来可复用指标函数，当前不提供可误触发的真实调用器。

Recall@6 / MRR / nDCG@6 按唯一文档计算，分级相关性用于 nDCG；没有相关文档的场景记 N/A，不计作召回成功。引用有效率和逐字匹配率仅统计实际引用；拒答率仅统计预期拒答场景；工具和未授权拒绝率各用适用场景作分母。报告同时记录 Token 已知值、未知用量场景、耗时、故障原因及各例来源。故意超时/凭证失效计入观测失败率，不能把它当不可预期故障率。Oracle 基于预期摘录生成输出，只证明协议与引用校验机制，**不证明 AI 答案正确、语义充分或真实模型抵御注入**。语义正确性永远标记人工评估；grounded 不作为准确率。

JSON 含数据集版本及 SHA-256、离线配置/Prompt 契约版本、模型/Provider、每例结果。比较仅在数据集、配置、Prompt 标识一致时计算差值；检索实现可以不同。配置/Prompt 的实际内容修改后必须同步提升契约版本。报告中的 Oracle 模拟 Token 不能用作真实费用估算。

## 检索决策

- 复用中文二字组 GIN 和英文 simple FTS GIN；中英词分别召回，每路最多 60 个候选，覆盖所有获授权知识库后统一合并。
- 增加有限、明确的中英词汇扩展和英语停用词。FTS 表达式只能由词法分析后的安全词构造，不接受用户 tsquery/SQL 片段。
- 对候选按词面覆盖率 >=0.4 过滤，保留已知恶意指令筛查；融合 FTS 两路及内容/标题覆盖排序，RRF 常数 60。该集验证整体修改有效，未单独证明 RRF 的独立增益。
- 沿用 1200 字分块、200 字重叠、页码/章节保存；长资料场景通过。本阶段没有足够证据更换分块算法。页码/章节仍从原解析器传递，引用须经当前租户、KB 授权、文档代次、逐字复核。
- PostgreSQL 实查无 vector 扩展：pgvector **DEFERRED**，未安装扩展/Embedding。Reranker **DEFERRED**：没有可验证的独立收益，不引入模型或依赖。

词面方法仍不能覆盖一般跨语言语义、任意同义表达或复杂矛盾；不能据此把真实模型质量标记通过。
