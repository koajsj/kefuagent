# P15-C 运维交接与验收闸门

本文是部署方的操作责任清单，不是生产验收或自动化执行记录。不要在记录中写入凭据、会话令牌、原始客户数据或连接串。现有生产、数据库和备份均须取得具体授权后操作。

## 入口、进程与权限

- 入口负责人确认 DNS、证书、HTTPS、精确 `WEB_ORIGIN`，限制数据库与 app 端口访问，检查 Nginx 全部站点的默认虚拟主机；替换示例域名并执行 `nginx -t`。直接对外代理须覆盖客户端转发头；多级代理只信任已知直接对端，检查伪造头和绕过代理路径。
- 配置代理速率/连接限制并启用应用共享入口限制；所有实例共享数据库、入口密钥和阈值。就绪端点也受限流，探针频率和来源须在目标环境验证；live 仅表示进程存活。代理限制不是 DDoS 防护保证。
- 应用使用非 root UID 10001，迁移身份不进入 HTTP 环境。数据库运行角色不是 owner 且不拥有绕过 RLS 能力；私有文档目录仅运行身份可读写。容器和卷权限在目标环境逐项核实，预检不会证明代理或业务行为。
- 停机负责人先阻止新流量，等待请求、模型/工具与文件操作排空，停止 app 并确认退出，再停止数据库。Compose 宽限期 180 秒不是完成保证；超时或崩溃后查业务记录、协调未知工具结果，不用新幂等键盲目重发。

## 一致备份与恢复闸门

1. 备份负责人记录版本、迁移 head、备份批次 ID、窗口和责任人；停止入口并排空所有写入、解析、删除、工具和模型操作。确认所有写入方停止后，按 [部署文档](DEPLOYMENT.md) 用经批准的完整备份角色导出 PostgreSQL，并在同一静止窗口保存文档目录及其权限。FORCE RLS 下必须核实备份角色能完整读取全部租户；普通运行角色不可用作全库备份。
2. 单独加密保管该批数据库密文所需的全部主密钥版本、活动版本标识和运行配置；关联批次而不把明文密钥放进数据库备份。保护备份及清单访问，记录校验值与完成状态，明确存储位置、保管人、恢复授权、保留期限及销毁方式。备份未完整或校验失败时禁止视为可恢复备份。
3. DBA 在获授权的全新隔离库与新文档目录恢复，禁止覆盖现有库、文档或备份；外部模型保持关闭、隔离网络并阻断真实入口。核查恢复退出码、迁移版本、表与文档完整性、权限/RLS、登录、租户隔离及凭证解密；失败不得切换。
4. 恢复可能复活备份后撤销的访客令牌、管理会话、成员/权限、凭证与已删除内容。安全和数据负责人须维护独立、受保护、可核对的备份后撤销及删除记录，在隔离目标上逐项重放并复核；若记录缺失或无法证明完整，保持入口关闭，由负责人决定进一步撤销或其他补救，不能声称恢复后安全。重放不得把已删除文件重新导入。
5. 安全负责人批准后才按另行批准的切换方案放量；记录操作结果与未解决差异。周期性演练和备份可用性告警由部署方安排，未演练不能推断可恢复。

## 轮换、保留与监控

- 依据 [P7 运行维护](P7_RUNTIME.md) 规划维护窗口，停止旧配置实例并排空请求，保留与全部未过期备份匹配的历史主密钥；先预览和核对，再分企业执行轮换并验证恢复。旧备份仍需旧密钥，过早销毁会永久丢失对应凭证。入口 HMAC 密钥轮换会改变计数命名空间，必须协调所有实例与窗口，不能当作限额恢复。
- 数据负责人确定业务、审计、文件及备份各自的期限、法律要求和审批；现有默认保留不是自动合规。清理先预览、批准，再按既有有界流程执行并记录结果；知识删除保留 tombstone 时按既有接口重试。新部署建议采用每日备份保留 7 天、每周保留 4 周、每月保留 6 个月的初始策略；负责人须结合本部署恢复目标审批并记录例外。这是交接基线，不是已配置的自动清理任务，不追溯删除已有备份。备份到期销毁和密钥退役须确认所有保留副本及恢复需求，不自行删除已有备份。
- 运维负责人设置并验证进程存活、就绪、数据库/磁盘容量、备份失败与过期、证书到期、入口拒绝和异常、模型错误/用量、未知工具结果及文档删除积压的告警；为每项指定接收人、阈值、响应时限和升级路径。应用未提供所有这些外部监控或自动修复。监控与日志限制访问和保留，不采集正文、认证材料、查询参数或供应商密钥；SSE 的完整交付不能由响应头耗时推断。

## 本轮边界

本轮仅在新临时 PostgreSQL 实例上完成合成数据恢复、3 个文档文件校验、2 个合成凭证轮换、恢复解密、缺失新密钥拒绝，以及撤销/删除记录重放和会话失效；实际证据见 [P15-C 交付记录](P15_C_ACCEPTANCE.md)。生产 HTTPS、容器构建与运行、非 root 卷权限、真实负载下停止排空、真实备份恢复、监控告警和真实模型均未获得验证。检查结果须按目标环境实际执行记录，不以静态检查或预检替代。
