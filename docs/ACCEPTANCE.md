## 安全边界结论

- 租户来自认证用户与有效成员验证；平台管理员不隐式绕过成员关系。组合外键、显式归属查询与 RLS 共同保护企业数据；全局身份/成员/公开定位/审计由显式服务授权，不声称全部表都有 RLS。
- 管理 Cookie 为 HttpOnly/SameSite Strict，写请求精确校验 Origin；Visitor 令牌独立、哈希存储、固定入口/配置版本/会话。跨访客/跨企业、管理认证混用、下线/撤销/结束/过期、I/O 中撤权均有针对性回归。
- AES-GCM 的 AAD 绑定企业和凭证引用，明文不回显；配置/凭证轮换及删除后交付复核。自定义公网 HTTPS Base URL、非 sk 格式 Key、Model ID 和备用路由保留，Mock Server 验证传输契约；白名单、公共 DNS 与固定 IP、禁跳转/代理的 SSRF 边界保留。
- 工具只调用静态只读能力，JSON Schema、Agent 授权、公开白名单、幂等、超时/中断及审计一致性有回归；模型输出不构成授权。提示注入测试只证明这些服务端边界和已知恶意模式，不保证任意真实模型攻击免疫。
- 前端用文本节点展示消息/引文，不执行或渲染输入 HTML/Markdown；没有管理 Token 的 localStorage。无通配 CORS，管理页 CSP 禁嵌入、公开聊天允许嵌入。
