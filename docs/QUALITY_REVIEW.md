# 静态质量审查与 AI 能力边界

长期工程规则见 [AGENTS.md](../AGENTS.md)。专用检索/模型评测执行器、评分模块、合成案例集和测试表单已移除；不保留第二套测试体系。历史指标只保留在阶段验收记录中，不代表当前代码效果，也不是继续运行评测的授权。

常规审查沿调用链核对：问题与上下文预算、来源归属与逐字引用、撤权后的交付检查、工具参数 Schema 和静态绑定、逐次授权、幂等、未知执行结果、Token/费用未知值、记忆同意与版本。结合 API/DTO、ORM/迁移声明和前端状态检查，记录证据、风险及影响范围。

静态检查可以发现契约或实现问题，不能证明召回率、语义正确性、自然语言质量、实际并发安全或生产容量。引用存在和逐字匹配也不是语义支持证明。缺少真实运行证据时标记 `NEEDS_RUNTIME_VERIFICATION`；需要运行应用、数据库、Provider 或浏览器时，先取得明确授权。

使用 `PASS`、`FAIL`、`NOT_RUN`、`NOT_AVAILABLE`、`NEEDS_RUNTIME_VERIFICATION`、`FALSE_POSITIVE` 标记结果。不得将未知指标按零计算、将 Demo 当真实模型或将历史指标当成本轮改进。

## 人工语义评审

审查范围包含中文复杂问句与同义表达、多文档综合、连续追问与条件修改、知识冲突、缺少证据与拒答、错误引用、工具选择与非法参数、权限撤销。先静态检查各分支的检索入口、上下文构造、结构化输出、Schema 和交付拒绝条件；需要实际材料才能判断的语义表现保留 `NOT_RUN`，不以静态检查补算分数。此范围是人工审查规范，不是案例数据集或自动评测任务。

取得明确运行授权并使用允许查阅的资料后，评审者应结合用户问题、完整相关上下文、实际提供给模型的证据和最终回答逐项判断：

- **检索**：相关来源是否进入候选结果，排序和截取是否保留适用条件；分别记录未检索到、未送入上下文和引用选择遗漏。
- **回答**：是否回答问题，事实、推断与不确定性是否区分，数字、时间、主体、否定、例外和适用范围是否准确；资料不足或冲突时是否适当拒答或转人工。
- **引用支持**：逐条检查回答中的事实性 claim，对照所标注来源的原文及必要上下文，判断支持、部分支持、矛盾或无法判断；多来源结论还要检查组合推理是否成立。引用存在或原文逐字匹配不能代替此判断。
- **交互与风险**：检查上下文衔接、表达清晰度、敏感信息、越权内容以及工具结果是否被误写成当前事实或承诺。

在现有审查记录中，按每条 claim 记录问题及回答版本、claim 原文或定位、引用编号及来源版本/位置、判断结果、缺失条件或矛盾依据、评审者和日期；无法访问来源或无法判断时明确记为未知。记录应遵守现有数据权限和脱敏要求，不复制不必要的客户信息。对分歧保留各自依据并复核，不以引用数量替代判断。

检索指标只描述指定样本和规则下的召回、排序或词面覆盖；人工语义判断描述该次被审材料中的支持关系与回答质量，二者不能互相推导。模型、提示词、知识库、检索配置或样本变化后，历史结果不能直接代表当前表现；没有实际评审的维度标记 `NOT_RUN` 或 `NEEDS_RUNTIME_VERIFICATION`，不计算或宣称质量提升。
