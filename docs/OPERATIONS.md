# 运行安全与后续真实模型验收

本阶段按用户选择只做离线改进，未发送真实模型请求。模型 ID、Endpoint、能力声明和价格必须由部署方确认；ChatGPT 订阅不是 API 凭证。没有新增运行依赖或自动清理调度。P7 已增加维护窗口主密钥 CLI 和显式确认的数据保留 CLI，见 [P7 运行维护](P7_RUNTIME.md)。

## 凭证和交付边界

沿用 AES-256-GCM、随机 nonce、`v1:tenant_uuid:credential_ref` AAD，ref 不可重命名。请求前在当前企业解析启用凭证，模型 I/O 后及结果交付事务再次检查配置版本、凭证启用/存在性和密文变更标记。交付事务锁配置及凭证行，更新/删除在提交点排序；在途轮换或删除使新结果失败且不落助手正文，但保留真实可得用量。内部密文 fingerprint 不通过 API 返回。

已提交历史不会因凭证轮换被删除。删除凭证后新请求安全失败，没有共享密钥或备用凭证旁路。已经发送给远端的请求无法由本地删除保证取消，仍可能收费；不承诺远端执行与数据库授权状态的分布式原子性。

模型错误只返回分类，不回传供应商原始错误正文、密钥、堆栈。仅明确模型不可用或不支持工具时才尝试已配置备用；429 的额度不足与普通限速区分。兼容性测试未证明任何具体厂商/模型能力。

## 主密钥轮换

P7 已实现版本化密文封装、新旧密钥兼容读取、单企业原子重加密、预览/检查/执行/恢复 CLI。必须停止旧配置进程并排空在途调用，保留全部旧密钥和可恢复备份；不提供在线热配置分发。具体命令、故障恢复边界见 [P7 运行维护](P7_RUNTIME.md)。普通企业 API Key 轮换继续使用原 HTTP 接口，与主密钥轮换不同。

## 用量与运行限制

部署变量详见 `.env.example`。企业、当前用户、Agent 三个范围都必须准入；跨 HTTP worker 通过 PostgreSQL 事务 advisory lock 串行统计/预留，不依赖进程内计数器。读取范围限当日、最近一分钟与仍活跃记录。GET `/api/v1/usage-limits` 返回部署限额、当前企业/用户用量；Agent 按实际调用配置单独准入。

- 模型最坏预留：RAG/连接测试一轮、Agent 最多五轮，每轮考虑主/备用及最多两次传输；按配置输入/输出上限计算。连接测试按 32 输出上限预留及发送。请求可能因保守预留提前拒绝。
- 完整且单次传输的步骤按返回 Token 结算；超时、进程丢失、重试未给全量账单时保留原预留到下一 UTC 日窗口，不将 null 当 0。部分已知 Token 可展示，不能解释为精确总账。没有供应商价格计费或金额硬上限。
- 幂等重放不会重复执行/准入。模型和工具循环/时间预算保留 P3 边界。旧记录迁移保守回填，以免把未知费用当作免费。
- 活跃调用到期后查询/后续调用归类结果未知，不自动重发。当前未配通用 HTTP 入口限流、生产负载验证或分布式配额账单核对；这些需上线前单独验收。UTC 日切换统计窗口不删除记录。

## 数据保留和删除规则

| 数据 | 当前规则 |
| --- | --- |
| 会话、消息、模型步骤、工具执行 | 默认保留；运维 CLI 支持预览、确认和有界清理，普通成员没有批量删除接口，默认无定时任务。 |
| 知识库、文档、分块及上传文件 | 企业管理员显式 DELETE；先不可检索，再幂等清文件/行。失败保留 deleting 记录供重试，禁止直接删存储目录。 |
| 引用过知识的历史消息/调用 | 保留已发生的摘录；后续模型上下文/重放验证当前有效来源。知识删除不等同全链路隐私擦除。 |
| 凭证 | 管理员显式删除，后续解析失败；数据库备份和已发送远端请求另有生命周期。 |
| 审计及用量预留 | 默认保留；不因业务失败或日切而删除。后续策略须保护审计完整性与幂等关联。 |
| 备份 | P6 仅创建新隔离演练副本，已验证恢复；未改动已有备份。生产期限与恢复由运营方单独批准。 |
| 公开入口、访客会话 | 发布可下线/不可恢复撤销；访客令牌 12 小时有效、结束后失效。过期不删除历史、用量、审计与幂等记录。 |

生产前必须确定期限、访问权限、法定保留、导出/擦除范围和恢复后的删除重放流程。不可将默认无限保留当成已完成的生产合规策略。

## 真实客服验收步骤（待授权）

1. 用户先确认 Provider、具体模型 ID、Endpoint 和首次测试总预算（币种/上限），再安全配置主密钥、主机白名单和企业凭证。密钥不粘贴聊天、不进入报告；用已有 `/model-credentials`、`/agent-configs` API 管理。先核对厂商的 JSON 输出、工具、Token 参数和温度支持声明。
2. 首次仅显式 POST `/api/v1/agent-configs/{id}/test-connection`（最多 32 输出 Token，仍可能收费），检查分类和用量。它只检查连接/解析，不证明工具调用能力。
3. 在独立测试企业复用 `tests/fixtures/customer_quality.json` 的 16 个通用场景，使用真实 Provider 逐项运行 `/chat` 或 `/agent-turns`，加入用户修改条件/切话题/长历史和工具返回注入变体。不得把离线 Oracle 输出作为模型回答；已授权真实只读工具由现有静态注册表执行，未授权/写工具仍由服务器拒绝。
4. 每例记录实际 Provider/模型、输入输出 Token（未知保留 null）、墙钟耗时、步骤/工具次数、来源、错误分类和人工答案正确性；多轮记录中间回合，复核跨企业/会话边界。降级/超时等不可安全制造的远端故障保留受控测试证据，明确未做真实故障注入。
5. 人工核对答案是否充分、引文是否支持结论、冲突/无证据是否拒答，注入是否泄露提示/凭证或诱发未授权动作；不能把 grounded 或 HTTP 200 当正确性。路由切换须验证完整历史仍在，未知网络结果不得盲目重试。先检查用量，不自动跑无限评估或使用全额预算。

目前没有真实模型自动评估执行器；离线脚本有意不支持 live 模式。真实质量、一般语义冲突、任意提示注入抵御和供应商实测能力仍未验证。后续真实模型阶段须另行授权补齐这些验收；P5 仅进行产品化离线验证，当前不实现任何行业连接器。

P5 补充：同源 Cookie、访客令牌、PUBLIC_RATE_KEY、公开额度、代理限流与三部分备份关系见 README 和 DEPLOYMENT。内部是企业成员共享会话；公开是逐访客能力隔离。P7 的维护窗口轮换与保留能力取代早期仅有方案的状态，验证范围见 P7_ACCEPTANCE。

P8 提供队列、负责人及协作历史、会话级摘录摘要、UTC 有界运营指标与访客反馈；口径及安全边界见 [P8 验收](P8_ACCEPTANCE.md)。保留预览包含备注、摘要和反馈关联计数，删除会话时级联；不自动清理数据。人工回复/内部备注提交结果未知时先查询历史，不盲目重发。预检命令和健康接口见 [P8 部署](P8_DEPLOYMENT.md)。
