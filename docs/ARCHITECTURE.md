# 第一阶段架构与实施记录

## P3 实施计划与边界

在 P1/P2 上增量实现：静态部署注册表（固定函数、版本、输入输出与副作用属性）→ AgentTool 授权 → 服务端逐次校验 → 持久 ToolExecution → 有界子进程执行 → tool 消息 → 模型继续推理。数据库定义不能指定代码或网络地址；本阶段只运行匹配注册表的低风险 read_only 工具，所有 write 默认 approval_required，不实现审批。

1. 先以失败契约/行为验证确定 Provider 原生 tool_calls 与 API；扩展 ToolDefinition，新增两张 FORCE RLS 表，复用 ModelCall/Message/AuditEvent。
2. 在现有 Provider 上支持工具定义、结构化调用与拒绝。新增 Agent turn，最多 4 次工具、5 次模型推理、120 秒整体预算；复用会话行锁与活跃调用唯一约束。
3. 持久幂等 reservation、执行前短事务授权、执行后再验权；网络与工具期间无数据库事务。未知结果不自动重新执行。写工具即使已获 Agent 授权也拒绝。
4. 验证真实只读工具进程、Mock 模型及故障工具的正常/连续/非法/撤权/跨租户/并发/重复/超时/崩溃/注入/审计行为，保留 P1/P2 回归。

主模型本会话实施；唯一 terra 只读复查安全。沿用用户指定 checkout，不创建 worktree、不提交，不进行真实 API 调用。数据库升级需先提供具体增量 SQL 并取得执行确认。仅维护本文与 README 的必要记录。

范围：独立通用客服后台基础，不依赖任何行业。无模型调用、推理循环、知识检索、前端、业务连接器。主模型实施，6.1terra 只读复核。

## 设计决策

- 同步 SQLAlchemy 2 + psycopg，FastAPI 同步路由在线程池运行。单个请求一个事务；API → 服务 → ORM，不增加通用仓储接口。
- users 为全局身份，tenant_memberships 唯一关联企业与用户，角色 admin/member、状态 active/inactive。平台管理员仅管理平台身份和企业；业务访问仍需有效成员身份。
- 不开放自行注册；CLI 交互创建首位平台管理员，无默认密码。平台管理员创建普通用户和企业，并指定已有启用用户为首位企业管理员；企业管理员可添加已有用户的 UUID，不可枚举全平台用户。
- Argon2id 密码；随机 opaque bearer 会话，仅存 SHA-256 摘要，固定到期、注销撤销。每请求复查用户/企业/成员状态；请求头 X-Tenant-ID 仅是企业选择器。无密钥内容保存，credential_ref 仅允许无路径、无 URL 的逻辑别名。
- 业务资源始终显式 tenant_id 过滤；配置、会话、消息、工具表启用并 FORCE PostgreSQL RLS。事务内 set_config(..., true)，无上下文默认拒绝，启动拒绝 SUPERUSER/BYPASSRLS 运行身份。身份/成员表需在选定企业前查询，依靠服务授权；审计查询也须显式授权和过滤。
- 消息以 (tenant_id, conversation_id) 复合外键关联会话。企业内共享工作区：有效成员可读配置、会话、消息和工具，可创建会话、写入三种角色的历史；后两种角色只是授权人员录入历史，不代表已调用模型或已执行工具。每条记录写入操作者。
- 企业、成员管理串行锁企业行，保护最后一位有效管理员；用户停用也检查其所有管理企业。配置更新必须匹配 expected_version，冲突 409。
- ToolSpec 为持久化声明，不接受 handler、代码、URL 或数据库对象。参数使用 jsonschema 库，支持有界的自包含 JSON Schema 2020-12 子集；禁止引用、正则、组合递归等潜在网络/计算风险。ExecutionContext 为服务端只读数据，无数据库 session；执行入口一律返回 rejected/execution_not_enabled，不注册可执行处理器。
- 成功管理操作与审计同事务；失败操作回滚后另事务写安全审计。审计不含输入正文、密码、token、Schema 参数值或 SQL；请求 ID 服务端生成。异常统一安全响应，响应不回显验证失败输入。

## 第二阶段实施决策

- 先针对六个指定仓库的解析、检索、来源和凭证源码调查，再沿用单体、同步 SQLAlchemy 与现有认证/租户依赖。无真实凭证，不进行外部模型验收。
- 本机 PG 17.11 未提供 vector 扩展；本阶段采用 PostgreSQL `simple` 全文检索和 GIN。策略接口独立；不安装 pgvector/Embedding，不宣称语义或混合检索。
- 增量新增知识库、文档、分块、加密凭证和模型调用表，全部 FORCE RLS；关联资源复合 tenant FK。现有配置增量添加 Base URL；消息增加服务端来源和调用关联，历史人工消息不提升权限。
- 文档服务器生成路径、大小限制、PDF/DOCX/TXT/MD 内容验证、子进程有界解析、分块页码/章节来源。同步解析有明确状态及租约；崩溃后显式重处理，删除使用持久 tombstone 与可重复清理。
- AES-GCM 用企业+凭证标识作 AAD，外部主密钥缺失则凭证操作拒绝。模型只允许部署方列出的 HTTPS 主机和公网解析地址、固定连接 IP、禁跳转/环境代理。
- 模型 HTTP 期间不占数据库事务：持久化调用/用户消息/会话活动租约后提交，结束时重新验证身份与引用。幂等键防同请求重复执行；未知的在途结果不得自动重发；超时/失败没有成功助手消息。
- 检索结果始终作为不可信数据，模型仅选择可回答证据与逐字摘录；服务器校验 chunk/quote、来源有效性并构造最终摘录答案。grounded 表示引用摘录经验证，不保证文档真实或自动证明语义相关性。无证据或非法引用返回 unresolved。历史只用成功的机器轮次，按有界输入预算截断。
- 先编写真实 PostgreSQL 和受控 Provider 的关键行为验收，再实施增量迁移、存储/解析、凭证/Provider、检索/对话、API/文档，最后做 terra 有针对性对抗审查与必要回归。

### 第二阶段验收与保留限制（2026-10-30）

结合 terra 意见与主模型检查，已修复：锁获取后 ORM 状态未刷新、并发重复删除、分阶段网络超时超过总预算、未知调用次数误记为零、连接测试调用中撤权后仍 running。模型进程有父进程整体超时及子进程独立闹钟，最多八个并发；解析有四个并发、RSS 监测及 CPU/时间/输入输出边界。文档存储与数据库没有跨介质原子事务，采用可恢复行状态和幂等删除；不是后台作业系统或 OS 安全沙箱。

已知模式过滤只是保守增强；最终 answer 由经过逐字/来源检查的摘录组成，不将模型任意自由文本标 grounded。语义可靠性、资料真实性和真实模型提示注入对抗尚未验证；无语义/混合检索。历史对话保留已发生的内容，知识删除不等同全链路隐私擦除。主密钥外部管理，在线轮换、数据保留、生产限流与运行角色分权是后续工作。

### P3 实际实现

- 两张新增表 AgentTool、ToolExecution，复合企业外键与 FORCE RLS；ToolDefinition 加版本/执行类型/输出 Schema；ModelCall 复用 reservation、会话互斥、步骤用量与结果来源；Message.source=agent、tool_call_id；审计扩展安全 details。0004/0005 为增量迁移，已取得用户对 dev/test 升级授权，未改写 0001–0003。不自动降级丢失执行审计。
- 静态能力注册和数据库声明分离；目前仅无副作用文本统计，写操作要求未实现的审批，默认拒绝。服务在每个 I/O 边界刷新身份；执行前 conversation → call → config → tool → grant 短事务，提交后运行子进程，执行后刷新/记账。交付检查使用刷新读，不引入跨配置锁反序。
- 工具/模型调用有各自限制和幂等边界，未知状态到期归类并保留记录，不自动重试工具。独立执行状态与 delivery_error 区分“已经执行”与“获准交付”；执行开始审计不是成功，终态审计与结果同事务。模型步骤用量持久化，任何未知总用量不伪造。
- 历史回答继承扁平 tool_dependencies（已有 ModelCall.result JSON，非新抽象表）。传输、重放、公开历史和管理查询均检查原执行所属 Agent/工具授权；依赖缺失 fail closed。历史最多 4 轮，最多 60 个继承执行依赖及本轮 4 次工具，避免无限递归/图遍历。
- terra 独立复核发现的执行后撤权误记 denied、输出缓存/回收、历史/查询交付旁路、锁反序及派生答案依赖遗漏，主模型逐项核实、修复并补关键回归；不是依靠提示词授予权限。结果注入可影响模型文字，不能授予服务器权限。子进程是故障边界，非恶意插件沙箱。
