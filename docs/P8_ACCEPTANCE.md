# P8 本机交付记录

## 范围与基线

本地基线 `2c86a5f` / P7 0.6.0；保留原有两处未提交收尾。P7 记录 54 项 Python（46.24 秒）、5 项 JS（约 0.1 秒），远端 CI 首次超时，后续未监控。P8 不把此 CI 缺口或 Mock 视作真实模型验收。用户另行允许交付时一次性远端 main 核对、正常推送和 SHA 核对，禁止 Actions 查询或轮询。

## 已实现

- **工作台**：复用会话和访客，7 类队列、标题搜索、负责人/优先级筛选、稳定时间排序和有界分页；有效成员分配/取消/转交、标签、分类、独立内部备注及协作历史。管理员可监督全部企业会话，成员只能控制自己负责的人工会话，可接管未分配或分配给自己的 waiting 会话。接管和变更使用行锁、版本冲突保护；关闭会话只能经管理员显式重新打开，不能通过恢复 AI 隐式重开。公开人工消息发送前复核入口、访客期限和发布版本。
- **记忆**：Agent turn 达到 12 个已完成轮次时，最多压缩 16 条旧用户消息，保留近期 4 个完整轮次；至少积累 8 条新旧消息才刷新。Provider 选择最多 12 条逐字用户摘录，保留诉求/用户报告/约束/决策/待解决分类、版本和来源范围。拒绝虚构内容；不把历史助手答案或内部备注提升为事实。摘要在最终问题 JSON 中作为不可信用户报告注入，当前问题优先；不能充当知识证据或授权。摘要步骤计入原调用配额、路由、用量、最多 5 步和 120 秒预算。
- **分析**：真实企业数据、UTC 半开区间最多 90 天，各类最多 10000 记录，超过范围明确拒绝；固定数量查询，不扫描消息正文。会话效率、AI 协作、引用/工具、Token/失败/模型分组、日趋势、分类、未解决会话、满意度。费用无验证价格，始终 null；Token 仅已知部分，未知计数单列。访客评价可在有效会话令牌期限内提交/更新，不能评价其他访客。
- **部署**：只读 preflight，检查角色/17 张 FORCE RLS 表及策略、head、密钥、匿名限流、目录、Origin、模型白名单和初始化；liveness、DB readiness、setup 分离。可选 app + PostgreSQL 17 Compose、私有持久卷、显式独立迁移配置，无自动管理员/迁移。macOS 原启动方式保留。

## 数据与口径

迁移 `0009_operations` 新增 collaboration、summaries、feedback 三表（FORCE RLS），新增会话运营字段与复合负责人/摘要来源外键。经明确授权，新建 `support_agent_p8_test` 从 0001 升级；现有 dev/test 仅增量升级 0009。没有重建集群、清库、修改已有备份或环境密钥；行为回归只写 P8 新库的合成记录。历史未知服务时刻不回填伪造值。

SLA 使用会话创建时间为基点：首次回复/当前人工等待 5 分钟，解决 24 小时；紧急为 1 分钟/1 小时，80% 标记即将超时。仅未关闭会话产生超时警示；时长未知为 null。无需定时任务。服务统计以区间内新建会话为 cohort，显示其当前处理状态；平均值只纳入有记录时刻的会话。转人工计 waiting 或实际 human。AI 独立解决是已解决、未转人工且最后调用 answered 的流程指标，绝不是语义正确率。趋势 AI/人工按曾否人工处理分类，模型总调用为逻辑轮次，分模型计 Provider 步骤（含摘要/备用）。引用比例仅当前调用落库时已验证来源，不保证文档事后未变更或业务答案正确。满意率分母只含已评价访客，不含未评价或内部会话。

新增表随会话删除级联；摘要随边界来源消息/生成调用删除清理，保留 CLI 预览纳入新关联计数。内部备注正文不写入审计摘要、不进入消息和知识检索。没有跨会话画像、写工具或行业适配。

## 限制

NOT_RUN：真实模型/摘要语义质量、GUI、Docker 构建/Compose 运行、生产 HTTPS/容量及故障切换；未查询远端 CI。不调用真实 API，不产生模型费用或部署远程服务器。P7 CI 通过条件仍未验证。

有界记忆不是无限历史：预算不足时不生成或不注入摘要；超过一批的存量积压需后续轮次逐批处理。近期旧答案仍是不可信历史；仅选择用户摘录不会证明用户陈述为事实。遗留 `/chat` 保留原 RAG 协议，自动摘要由工作台/公开采用的 `/agent-turns` 驱动。没有无损长期记忆或完整注入免疫承诺。首次响应以会话创建为基点，不推断线下回复。内部成员共享企业会话可见性，负责人只限制人工控制和元数据更新；不提供私人收件箱。人工备注/人工回复网络结果未知时需先查询历史，未新增幂等承诺。公开会话结束后令牌失效，反馈需在结束前提交；不放宽原访客认证以增加评价。

## 发布准备

用户明确允许先单独提交原有 P7 收尾，随后提交 P8；发布前后仅一次性 Git main 核对和正常推送，不查询 Actions。保留历史记录的时间语境：P7 文档中的“未推送”指当时状态，不代表本轮获授权的提交。最终提交 SHA 与推送核对以本轮交付消息及 Git 历史为准。
