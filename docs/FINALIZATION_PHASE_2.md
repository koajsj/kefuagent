## 3. 综合回答与无证据边界

现有回答链保留：检索当前有效来源 → 有界证据输入 → 模型选择证据 → 结构/ID/原文/代次/授权校验 → 包含上下段条件的安全摘录，失败或冲突返回未解决。第一阶段的完整知识输入依赖与当前授权复核继续有效，未因优化缓存而删除这些检查。

`evidence_synthesis` 仍是明确标注的综合草稿：每条结论关联原始来源 ID，区分 fact / inference / uncertain，保留原文对照；`semantic_verified=false`，自由生成文本不被升级为已验证事实。现有显式标签冲突筛查只是保守规则，不能识别所有自然语言矛盾。不得因带引用认定答案正确；无证据不生成政策承诺。此阶段改进切片/输入和执行开销，没有声称已解决通用语义蕴含验证。

## 6. 路由、预算、用量与费用

沿用轻量任务启发式、模型能力声明与工具协议检查；普通问题不会仅因工具存在就强制选推理模型。主备仅处理既定可确认失败类别；未知结果不盲目换模型重试。第一阶段每次付费调用保守 Token 预留、金额预算、精确端点价格上界、跨日未知预留与超时保护继续保留。

**FIXED**：运营概览原先把所有调用费用写成 unknown，即使持久化步骤有完整用量/价格。现在复用 `costs.estimate` 与调用时价格快照，按币种累计已知小计，缺价/缺用量按逻辑调用计未知；未派发且无步骤的调用不产生外部模型费用。不跨币种相加，不使用当前价格追算历史，不把未知补零。输入最多 10000 调用的原有查询上限保留，仅流式读取计价所需 JSON，逐条累计。

API 增加 `known_cost_subtotals`、`cost_complete`；旧 `known_cost` 仍为 null 兼容原契约，React、旧管理页和 Demo 同步。Demo 不冒充真实费用。单次调用详细费用与 Trace 继续显示估算依据/已知小计/未知步骤，不构成供应商账单。
